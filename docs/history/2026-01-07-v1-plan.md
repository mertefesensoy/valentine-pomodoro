## 2. Architecture Upgrades (Critical)

### 2.1 Notification ID Tracking
**Problem**: Calling "cancel all notifications" will cancel *all* of your app's scheduled notifications, which breaks if you add other features later (reminders, motivational nudges, etc.).  
**Solution**: Store `scheduledNotificationId: string | null` in `TimerState` and cancel only that specific notification.

### 2.2 Session Duration Capture
**Problem**: If user changes focus duration mid-day, stats will be inaccurate (adding old sessions with new duration).  
**Solution**: Store `sessionPlannedMinutes: number | null` when starting a session, and use that value for stats (not current settings).

## 3. Data Model (TypeScript Types)

```typescript
// Timer phase
type TimerPhase = 'focus' | 'shortBreak' | 'longBreak';

// Timer state (persisted)
interface TimerState {
  phase: TimerPhase;
  isRunning: boolean;
  endAt: number | null;              // epoch ms when running
  remainingMs: number | null;        // cached when paused
  completedFocusCountInCycle: number; // 0..N for long break logic
  scheduledNotificationId: string | null; // ID of the scheduled notification (cancel specific one)
  sessionPlannedMinutes: number | null;   // Actual duration used for this session (stats accuracy)
}

// Settings (persisted)
interface Settings {
  durations: {
    focus: number;                   // minutes
    shortBreak: number;
    longBreak: number;
  };
  longBreakEvery: number;            // e.g., 4
  notifications: boolean;
  sound: boolean;
  haptics: boolean;
  showLoveNotes: boolean;
}

// Stats (persisted, keyed by YYYY-MM-DD)
interface DayStats {
  focusSessions: number;
  focusMinutes: number;
}
type StatsMap = Record<string, DayStats>; // { "2026-01-07": {...}, ... }

// Gift mode (persisted)
interface GiftMode {
  hasSeenGiftMode: boolean;
}

// Love notes (persisted)
interface LoveNotes {
  notes: string[];
}
```

## 5. Core Logic Implementation

### 5.1 Timer Logic (Critical - Must Be Correct)
**Principles**:
- **No decrementing counters**: Always compute `remainingMs = endAt - now`
- **Foreground/background safe**: Recompute on app focus
- **Persist state**: Save `endAt` and `isRunning` to AsyncStorage

**State Transitions**:
```
[Idle] --Start--> [Running] (set endAt = now + durationMs)
[Running] --Pause--> [Paused] (cache remainingMs, clear endAt)
[Paused] --Resume--> [Running] (set endAt = now + remainingMs)
[Running] --Complete--> [SessionEnd] (trigger notification, update stats, transition phase)
[Any] --Skip--> [Next phase]
```

**Phase Transitions**:
- `focus` → `shortBreak` (unless cycle count ≥ longBreakEvery)
- `focus` → `longBreak` (if cycle count ≥ longBreakEvery, then reset cycle)
- `shortBreak` → `focus`
- `longBreak` → `focus`
- **Default**: Do NOT auto-start next phase (user must press "Start")

**Stats Update**:
- Only increment on `focus` completion
- Update `stats[todayKey].focusSessions += 1`
- Update `stats[todayKey].focusMinutes += sessionPlannedMinutes` (use the duration captured at session start, NOT current settings)
- **Why**: If user changes focus duration mid-day, stats will be accurate to what was actually used

---

### 5.2 Notifications
**Flow**:
1. Request permission on app start (if not granted)
2. On session start (if running):
   - Schedule notification for `endAt` timestamp
   - **Store the returned notification ID** in `TimerState.scheduledNotificationId`
3. On pause/skip/reset:
   - Cancel **only the specific notification** using stored ID (not "all notifications")
   - Clear `scheduledNotificationId`
4. On completion:
   - Show notification with cute copy (see below)
   - Play sound (if enabled)
   - Trigger haptics (if enabled)
   - Set up foreground notification handler (iOS shows notifications even when app is open)

**Critical**: iOS notifications ONLY work on real devices, not simulators. Test using Expo Go on a physical iPhone.

**Notification Copy**:
- Focus complete: "Focus complete 💗 time for a sweet break"
- Break complete: "Break's over 💘 back to your goals"

---

### 5.3 Persistence Strategy
**Keys**:
- `timer_state`: TimerState (JSON)
- `settings`: Settings (JSON)
- `stats`: StatsMap (JSON)
- `gift_mode`: GiftMode (JSON)
- `love_notes`: LoveNotes (JSON)

**Helpers** (`src/utils/storage.ts`):
```typescript
async function save<T>(key: string, value: T): Promise<void>;
async function load<T>(key: string, defaultValue: T): Promise<T>;
```

**When to Persist**:
- Timer state: after every action (start, pause, skip, complete)
- Settings: on change
- Stats: on session complete
- Gift mode: after first dismissal
- Love notes: on add/edit/delete

## 9. Risk Mitigation

### 9.1 Timer Accuracy
**Risk**: Timer drifts or breaks on app backgrounding  
**Mitigation**: Always compute from `endAt` timestamp, never decrement a counter. Test with app in background for >25 min.

### 9.2 Notifications on iOS
**Risk**: Notifications don't fire on iOS (permissions, background limits)  
**Mitigation**: Request permissions explicitly, test on real device (not simulator). Add fallback UI alert.

### 9.3 AsyncStorage Failures
**Risk**: Data loss on corrupt storage  
**Mitigation**: Wrap all AsyncStorage calls in try/catch, provide sensible defaults. Log errors to console (dev mode).

### 9.4 Expo Managed Workflow Limits
**Risk**: Needing a native module (e.g., custom sound player)  
**Mitigation**: Use only Expo SDK modules. If needed, switch to EAS Build (still managed, no prebuild).
