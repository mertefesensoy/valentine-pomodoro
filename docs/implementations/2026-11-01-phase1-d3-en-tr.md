## 1. Problem / Motivation

D1 put the translator in place and D1 and D2 wrote every string of the rebuilt screens as a key, in English and draft Turkish. What's left still speaks only English:
- **Fly:** its buttons ("Start flight", "Pause", "Reset", "Resume"), "Landed!", "From" and "To", the map hints, the camera mode names and every accessibility label;
- **the airport picker** and **the love note card** that Fly still shows;
- **the session notifications:** "Focus complete 💗", "Time for a sweet break", "Break's over 💘", "Back to your goals", Fly's landing;
- **the update prompt:** "Update available", "You have the latest version", "Not now", "Update";
- **the not-found route:** "404" and "Go to Home".

So a Turkish phone shows Turkish everywhere except Fly, the notifications and the update prompt. And nothing stops the next English literal from slipping in.

The owner also asked (2026-10-31) for a Language row in Settings: System, English and Türkçe. Today the only switch is iOS's own per-app setting.

## 3. Implementation Approach

### 3.1 Three checks, and how the language choice could apply

The plan (§3.4) leaves open how the Language row works. Three facts decide it:
1. **Who reads the language, and when.** The translator fixes the language for the process: its contract says "calling it in render is pure", and ADR-0048 rests on that. `WeekStack.tsx` computes its date locale once, at module load (`const LOCALE = language === 'tr' …`). `TimerScreen`'s "Break at" clock, `formatNumber`, `upper()` and the notes store read it at call time. Switching at once would need every module-load reader turned into a call-time one, a mutable language and a remount of the whole tree: a change to the translator's contract, so an ADR of its own.
2. **Storage at start-up.** `appStorage` (MMKV, `src/utils/appStorage.ts`) is synchronous, and `hydrateStores` already reads it before the first render. A choice stored under its own key can be read by `deviceLanguage()` when `src/i18n/index.ts` loads. That's additive, not a migration: the settings blob and its migrations stay untouched.
3. **No relaunch API.** `expo-updates` isn't installed (the update prompt is an App Store version check), so the app can't restart itself.

**The three ways, for the owner:**
- **(b1) In-app, at the next launch** (recommended): the row stores System, English or Türkçe under its own key; `deviceLanguage()` reads it first. The row says the change applies when the app next opens. It keeps the translator's contract and ADR-0048 as written.
- **(b2) In-app, at once:** the same row, and the app redraws in the new language straight away. It needs the contract change above and a new ADR, and the tree's remount drops any open sheet.
- **(a) iOS's own page:** the row opens Settings › Apps › Valentine Pomodoro (`Linking.openSettings()`), where iOS relaunches the app in the chosen language. But iOS shows that page's Language row only when the phone lists two or more preferred languages, so a one-language phone needs a fallback.

### 3.2 The raw-text check

A Jest test parses every `.ts` and `.tsx` file under `src/` and `app/` (not tests or fixtures) with `@babel/parser` (`typescript` and `jsx`), and fails on user-visible English outside the string files:
- JSX text with two or more letters;
- string or template literals in `accessibilityLabel`, `accessibilityHint`, `placeholder`, `title` and `label` props;
- literal first and second arguments to `Alert.alert`;
- literal `title` and `body` in a notification's `content`.

One file is allowed, with its reason in the script: `src/startup/StartupDiagnostics.tsx`, B7's hidden diagnostics panel, which only the developer opens.

**What it doesn't see:**
- **Calls** aren't looked into, since `t('fly.start')` passes a key, not text.
- **Comparisons** aren't either (`phase === 'focus'`).
- **Literals in constant tables:** Fly's camera-mode names sat in a `MODE_LABEL` object, which the check can't tell from code. They were found by reading Fly and extracted all the same.

### 3.4 The language choice, as built

**The owner, 2026-11-01:** "At the next launch is fine" (way b1 of §3.1).

**How it works:**
1. **Settings › Language** offers System (the default), English and Türkçe. Tapping one stores it at once under `language_choice` (System removes the key).
2. **Nothing on screen changes.** The footer says "A change takes effect after you close and reopen the app." ("Değişiklik, uygulamayı kapatıp yeniden açtığında geçerli olur.").
3. **At the next launch,** `src/i18n/index.ts` reads the key once when it loads. A stored English or Türkçe wins; System follows the device's preferred languages, as before D3.

**Contracts:**
- `readLanguageChoice(): 'system' | 'en' | 'tr'`: the stored choice. Nothing stored, or anything else, reads as 'system'.
- `saveLanguageChoice(choice)`: stores it; 'system' removes the key. Side effect: one MMKV write. It applies at the next launch.
- `resolveLanguage(choice, codes)`: pure. A choice other than 'system' is the language; otherwise `pickLanguage(codes)`.

**The invariant kept:** the language is fixed for a process (the translator's contract, ADR-0048), so `t` stays pure in render and nothing subscribes to it.

**Why the key is read straight through MMKV:**
- `utils/storage.ts` refuses to read before the one-time AsyncStorage migration has finished, and the translator loads before then.
- That's safe because the key is new in v1.4: the migrator copies only v1.3.1's keys, so it never writes this one, and Settings writes it only after the stores have hydrated.
- The storage migration itself is untouched.

**Reset settings leaves the choice alone,** as it leaves Classic's layout. Reset must never change the language behind a restart, and its message lists what it resets.

**What a language change doesn't change:**
- ~~The love notes already stored stay in the language they were seeded in.~~ **Amended after build 56 (§3.8):** the default notes show in the app's language; the person's own notes stay as written.
- A notification scheduled before the change keeps its language.

**The labels:** "English" and "Türkçe" are each written in their own language in both string files, as iOS's own language lists do, so a person who can't read the current language still finds theirs. "System" is translated.

### 3.8 The default notes follow the language; the footer's Turkish

**The owner, 2026-11-01:**
- "Sure change it": "telefonun kilitliyken" becomes "telefon kilitliyken" (`settings.notifications.footer`, §3.6).
- "When i changed the language to turkish the default notes did not turn into turkish": §3.4 had decided that kept notes stay in their language. Build 56 showed what that means: a Turkish Notes tab full of English defaults.

**What the list held,** on the owner's install:
- **v1.3.1's frozen set** (`legacyLoveNotes.ts`), which the storage migration keeps for existing installs.
- **v1.4's defaults,** added in English by Restore in build 52.
- **The owner's own notes.**

v1.4's 20 defaults and its fallback have Turkish versions, in the same order. v1.3.1's set has none, but **12 of its 20 notes are the same sentence as a v1.4 default** in letters and digits, give or take punctuation or emoji. The other 8 aren't:
- "Bengisu, tiny focus — big love 💗" and "You're amazing, Bengisu", which name her;
- "One pomodoro closer to your dreams", "Small steps, big heart 💘", "Keep going, you're unstoppable", "You make hard work look easy", "Pomodoro by pomodoro, you're shining", "Tiny victories, infinite love" and "Break time = self-care time 💕".

**The fix: change what's shown, never what's stored.**
- `noteInLanguage(note, lang)` (`notesStore.ts`, pure):
  - a note that matches a default **in the other language**, by `noteKey` (letters and digits, lower-cased), returns that default in `lang`;
  - every other note returns as stored: the person's own, an edited default, the 8 v1.3.1 notes without a Turkish version, and a default already in `lang`.
  - So in English, v1.3.1's "Gentle focus, strong heart 💗" keeps its 💗; in Turkish it reads "Sakin odak, güçlü kalp.".
- **Used by:**
  - the Notes list (`LoveNotesScreen`);
  - the editor's starting text (`NoteEditor`), so saving an untouched note changes nothing (Save stays off), and an edit stores the person's own text;
  - `pickRandomNote`, so Classic's love note, Fly's landing note and the preview all follow the language.
- **Why not rewrite the stored list on a language change:** a round trip through the other language would replace v1.3.1's own wording with v1.4's, losing its punctuation and emoji. Shown, not stored, switching back loses nothing, and the storage migration stays untouched.
- **Restore counts a default as present in either language** (`defaultPosition`), so Turkish Restore never adds a default the list keeps in English.

**A bug the tests caught:** the fallback note is the same sentence as the first default ("Tiny focus, big love 💗"; "Minik odak, kocaman sevgi 💗"). Built last into the position map, it took over position 0, so Restore saw the first default as missing. Each key now keeps its first position.

## 5. Design Decisions

| Decision | Alternatives considered | Why this one |
|----------|------------------------|--------------|
| The raw-text check is built before the extraction | Extract first, then add the check | Its first failing run lists what's left, file by file, and proves the check catches each kind it claims to |
| A stored language choice gets its own MMKV key | A field in the settings blob | `i18n/index.ts` loads before the stores hydrate. Its own key is read directly and needs no settings migration |
| The diagnostics panel is allowed English | Translate it | It is the developer's tool behind a hidden gesture (B7); nobody else sees it |
| The airport picker takes a `title` | Keep building "Select {label}" from "From" and "To" | Turkish can't put the label into that sentence; a full name also reads better to VoiceOver |
| Notification emoji stay in code | Move them into the string files | The emoji check scans the JSON files; the words translate, the emoji don't |
| The language choice applies at the next launch | At once (a remount and a new ADR); iOS's per-app page | The owner's choice. It keeps the translator's one-language-a-process contract, and needs no relaunch API, which the app doesn't have |
| Reset settings leaves the language alone | Reset it to System | Reset would change the language behind the next restart, which nobody would connect to the Reset; Classic's layout is left alone the same way |
| "English" and "Türkçe" in their own language | Translate them ("İngilizce", "Turkish") | A person who can't read the current language still finds theirs, as in iOS's own lists |
