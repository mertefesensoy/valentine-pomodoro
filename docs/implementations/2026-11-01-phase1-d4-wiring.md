## 1. Problem / Motivation

- **The sounds existed but nothing played them.** D4 made three sounds (focus start, break start, completion) and re-encoded Fly's loop as a seamless one. They sat on `phase1/d4-sounds`, and the app had a Sound switch in Settings that switched nothing: DEF-007's sound half.
- **One shared audio session.** Fly's ambience sets the app's audio mode to play through the silent switch. The UI sounds must respect the switch (FR-SET-004), so they can't simply share Fly's mode.

## 3. Implementation Approach

**When each sound plays:**

| Sound | When | Where |
|---|---|---|
| Focus start | Start focus, from idle | `handlePrimaryAction`, before `start()` |
| Break start | Start break, from idle | The same |
| Completion | A focus completes and its sticker lands, with Timer in front | The placement's effect, on the frame its haptic fires: the file opens with its pop, so it starts with the spring (D4 record §8) |

- **Nothing on Pause, Resume, Skip or End.**
- **No phase starts on its own:** a completed focus leaves its break waiting for Start, so no sound plays without a tap or a sticker.
- **A break's end has no sound.** D4's completion sound is the sticker's, and a break's end gets its notification when the app is in the background.
- **Fly plays none of them;** it keeps its ambience and its landing notification.

**Contracts (`src/audio/uiSounds.ts`):**
- `loadUiSounds()` creates the three expo-audio players, once; later calls do nothing.
  - Classic queues it with `runAfterFirstFrame('sounds.load', …)` (B7's deferred queue), so it never runs on the cold-start path.
  - `playUiSound` loads the players itself if a sound is asked for first.
- `playUiSound(name)` plays one from its start (`seekTo(0)`, then `play()`), unless Settings › Sound is off, which it reads at the moment it plays.
  - All three play at full volume: D4 balanced them within 0.4 LU of one another.
- `applyUiAudioMode()`: `setAudioModeAsync({ playsInSilentMode: false, interruptionMode: 'mixWithOthers' })`. On iOS that's the `.ambient` category (`expo-audio/ios/AudioModule.swift`): the silent switch and the screen lock silence it, and it mixes with the person's music instead of pausing it.
- **Nothing throws:** a player that can't be made, or a play that fails, leaves that sound silent and the timer running.

**The shared audio session:**
- **The two modes never play at once.** Fly's hook sets `playsInSilentMode: true` when Fly's screen mounts, and Fly's screen (with its player) unmounts when Classic shows.
- **Coming back from Fly,** in the same effect that switches the session clock back, Classic sets the UI mode.
- **At launch,** the deferred task sets it too, unless the app opened straight into Fly.

### 3.1 The notifications' sound

**The owner, 2026-11-01:** "We can add this i would want that".

- **Before:** the session-end and daily-reminder notifications were scheduled with `sound: false`, under the comment "We handle sound separately via expo-audio", written when nothing played. So a locked phone got a silent banner at a phase's end, and iOS ties vibration to the sound.
- **Now:** both carry `sound: 'default'`, the system's notification sound, and with it the vibration.
- **D4's files can't be used here:** an iOS notification sound must be Linear PCM, IMA4, µ-law or a-law in a `.caf`, `.aiff` or `.wav` file, not AAC in `.m4a`.
- **With the app open,** the handler (`App.tsx`) still plays no sound: Classic's own sounds play instead, so a completion never sounds twice.
- **Android** keeps its channels' own sound settings; nothing there changed.

## 5. Design Decisions

| Decision | Alternatives considered | Why this one |
|----------|------------------------|--------------|
| The UI sounds use `.ambient` (`playsInSilentMode: false`, `mixWithOthers`) | Fly's `.playback` mode | FR-SET-004 asks the sounds to respect the silent switch; a chime must never pause someone's music |
| Classic sets the mode when it comes back from Fly | Set it before every sound | Setting it is asynchronous and would delay the completion sound past the sticker's spring; the two modes never overlap, so the switch between screens is the one moment it changes |
| Completion plays with the sticker placement, only with Timer in front | Play at every completion, wherever the person is | It's the placement's sound (D4's design); it follows the placement's haptic, which has the same condition |
| Start plays a sound; Resume doesn't | A sound on Resume too | The sounds mark a phase beginning; Resume continues one |
| Fly plays no UI sounds | Focus start on Start flight | Fly has its own ambience and audio mode; the plan's three sounds are Classic's |
