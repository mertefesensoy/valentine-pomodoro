## 3. Implementation Approach

### 3.1 Telling a Mac apart

`IS_MAC = Platform.OS === 'ios' && Device.deviceType === Device.DeviceType.DESKTOP`, read once.

- expo-device returns `DESKTOP` when `ProcessInfo.isiOSAppOnMac` is true (`node_modules/expo-device/ios/DeviceModule.swift:88`).
- That is false on iPhone and iPad, and false for a Mac Catalyst build, which this app doesn't have.
- It's a constant for the process's life, so a tree that branches on it never remounts.
- `jest.setup.ts` mocks it as false, so no existing test changes. The tests that need it true mock it themselves.

### 3.2 The banner on a Mac

- **One banner for the whole app.**
  - On a Mac, `app/_layout.tsx` puts the root `Stack` in a `flex: 1` view, with `MacBanner` below it, so the banner keeps its own slot at the bottom of the window.
  - Every tab and screen is laid out above it, never under it. Form sheets and the full-screen welcome are presented over it.
  - On iPhone and iPad the tree is the one build 66 was checked with: no wrapper, no banner.
- **Stats:** on a Mac, the Stats banner and its slot aren't rendered, so Stats never shows two banners.
- **Its width:**
  - The library sizes an anchored adaptive banner from `UIScreen.mainScreen.bounds`, not the window (`RNGoogleMobileAdsCommon.mm:211-216`).
  - So `MacBanner` passes `width`, the window's width from `useWindowDimensions`, rounded down. A change of `width` requests a new banner (`RNGoogleMobileAdsBannerView.mm:60-62`).
  - The width settles first: a new value is passed only once the window has kept it for `MAC_BANNER_RESIZE_SETTLE_MS` (1,000 ms). Dragging the window's edge therefore sends one request, not one per frame.
- **When it asks:** after `AdManager.init()` has settled, so after the first frame and after the SDK's `initialize()`. The Stats banner waits for its tab's first focus in the same spirit.
- **What it asks for:** `BANNER_ID`, `ANCHORED_ADAPTIVE_BANNER` and `requestNonPersonalizedAdsOnly: true`, the same as Stats.
- **How it looks:**
  - With no ad, the slot takes no height and draws nothing.
  - With an ad, it gets the paper background and a top hairline in the edge colour, as on Stats, plus the bottom safe-area inset.
- **The interstitial** on a Mac follows FR-ADS-001 unchanged ("Both").

**What the hidden panel shows.** An empty bottom edge on a Mac could mean no fill, a request error, or a Mac not detected at all. Telling them apart shouldn't cost another build, so the banner reports to `bannerStatus`, as the Stats banner has since build 46 (B6 fix). B7's hidden panel (a long-press on Settings → About) shows a line such as:
- `Mac banner (this launch): loaded 1180×90 · asked 1180 pt`
- `failed: googleMobileAds/no-fill (…) · asked 1180 pt`
- `not a Mac`

Its "Share data" carries the same, with `isMac`.

**`MacBanner`'s contract:**
- **Inputs:** none.
- **Output:** `null` unless `IS_MAC`.
- **Side effects:** one banner request when `init()` settles, and one more each time the settled width changes.
- **Invariant:** mounted once, by the root layout.

### 3.3 The display on a Mac (DEF-010 there)

A local Expo module, `modules/mac-display-awake`, which autolinking picks up from the `modules/` folder at EAS prebuild (`expo-modules-autolinking`'s default `nativeModulesDir` is `./modules`, and a folder there needs no `package.json`).

- **Swift, `MacDisplayAwakeModule`:**
  - `hold()` and `release()` record whether a session wants the display, and apply that on the main queue.
  - While it's wanted, and the app is in the foreground, and `ProcessInfo.processInfo.isiOSAppOnMac` is true, the module holds one `ProcessInfo.beginActivity(options: [.userInitiated, .idleDisplaySleepDisabled], reason:)` activity. Otherwise it ends it.
  - Entering the background ends the activity, and coming back re-applies it, as expo-keep-awake does with its idle timer.
  - **On an iPhone or iPad the module does nothing**, so 1.5.1's path there is unchanged.
  - Each closure hops to the main queue and calls a `@MainActor` method. expo-status-bar's `StatusBarModule`, already linked and also built as Swift 5.9, does the same, which lowers the risk of the first compile. The module has never been compiled here.
- **JavaScript, `modules/mac-display-awake/index.ts`:**
  - `holdMacDisplay()` and `releaseMacDisplay()`.
  - They do nothing when the native module isn't there: on Android, on the web and in Jest (`requireOptionalNativeModule`).
- **`useKeepScreenAwake`:** wherever it activates or deactivates `KEEP_AWAKE_TAG`, it also holds or releases the Mac display.

**Why this API:**
- Apple documents `beginActivity(options:reason:)` and `.idleDisplaySleepDisabled` ("A flag to require the screen to stay powered on") on iOS 7.0+, iPadOS and Mac Catalyst 13.1+. It's public API.
- On a Mac it is the call macOS apps make.
- Its effect in an iPad app on a Mac wasn't found documented, and only the Mac check can show it.

## 4. Mathematical / Statistical Details

**The banner's width.** Let $w(t)$ be the window's width in points at time $t$, and $S = 1000$ ms. The width passed to the SDK, $b(t)$, starts at $\lfloor w(0) \rfloor$. It changes to $\lfloor w(t) \rfloor$ only when $\lfloor w \rfloor$ has kept that value for the whole interval $[t - S, t]$. A resize that ends at $t_e$ therefore makes one request, at $t_e + S$. A window that is resized and put back within $S$ makes none.

## 5. Design Decisions

| Decision | Alternatives considered | Why this one |
|----------|------------------------|--------------|
| A root-layout slot on a Mac | A banner inside each tab | One banner, one request, every tab, and no screen has to change its layout. |
| The wrapper only on a Mac | The wrapper everywhere | iPhone and iPad keep the tree that passed build 66's check. |
| `IS_MAC` from expo-device | The new module's own `isiOSAppOnMac` | The banner then doesn't depend on the new native code; expo-device is already a dependency and reads the same flag. |
| `beginActivity(.idleDisplaySleepDisabled)` | IOKit's `IOPMAssertionCreateWithName` | IOKit's power API isn't public in the iOS SDK, the one this app is built with. |
| Gate the module on `isiOSAppOnMac` in Swift | Call it on every device | Nothing changes on the iPhone, which passed its check without it. |
| The module in its own commit | One commit | If build 66's display stays on with a Mac (check M3), the module can be dropped on its own. |
| The same banner ad unit as Stats | A new ad unit | No new unit has been made in AdMob. A Mac unit would only separate the reports, and can come later. |
